Notes:
  - total set discoveries and permuted-null counts are over the same multi-gene cluster universe.
  - nominal p<0.05 is the uncorrected upper reference, not a valid FDR control.
  - every cluster is tested against all ~896 sets (ora tests the full universe per group), so BH divides the
    best hit by that count; the strongest single hit anywhere is p=4.4e-04, giving min BH q=0.39.
  - Storey and two-stage BH do not help: a 2-8 gene cluster leaves almost all sets genuinely null (pi0~1),
    so the adaptive pi0 factor is near 1 and the adjusted values track plain BH.
  - restricted-universe (conventional overlap-based ORA), corrected WITHIN each cluster over only the sets its genes hit:
    (f) a>=1: REAL 0/16 (0 discoveries), PERMUTED-NULL 0/17; (g) a>=2: REAL 3/16 (61), NULL 0/17; (h) a>=1 Storey: REAL 2/16 (83), NULL 0/17.
  - a>=1 barely shrinks the universe: each cluster's 2-8 genes still hit ~306 of 896 sets (every gene sits in many GO/Reactome sets), so BH over ~300 tests still buries the best hit and (f) recovers 0/16. Only a>=2 (two of the cluster's genes co-occurring in a set) cuts the universe hard enough to recover 3/16.
  - The permuted null stays clean across every restricted method (max 0/17), so restricting the universe is NOT an artifact of fewer tests: the few recoveries are real signal, not shuffled noise clearing an easy bar.
  - CONCLUSION: restricting the test universe is the legitimate lever, and it does recover REAL enrichment the whole-net correction misses (3/16 vs 0/16 for BH over all 896 sets), with a clean permuted null. But even conventional ORA recovers only a handful, nowhere near the paper's 19/22. So the honest read is that the per-cluster signal is real but WEAK at construct level with GO-BP + CORUM + Reactome: G8 is only partially reproducible here, and the earlier curated-collection count remains the right graded number rather than the broad net.
